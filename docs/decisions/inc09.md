# Decisions — Increment 09: Cheat guards

## Critical checkpoint (written before any code)

**Rollback point:** `1528187` (Merge pull request #19, `feat/inc08-validator`), the last merged commit on `main` when this increment started.

**Failure signs.** If any of these appears, a "pass" can no longer be believed:

1. A guard misses a cheat in the AT-07 set: any fixture in `packages/core/test/fixtures/patches/` other than the honest ones gets `ok: true` or names the wrong guard.
2. An honest fix to a source file is rejected (a false positive): `honest-rename.diff` or `honest-refactor.diff` gets any guard name.
3. A cheating patch reaches the container: the validator is called for a patch that failed a static guard.
4. A verdict says `cheating` without a guard name, or names a guard on any other outcome (DR-04).
5. An empty `catch` that was already in the file, and that the patch did not touch, is flagged.
6. The count guard lets a run through when a test that existed before is gone afterwards, even if the totals match.

**Isolation protocol.** Run each guard on its own against every patch fixture (a table test: guard × fixture → expected hit or no hit). Then run `runStaticGuards` with all the guards together and check that the first guard in the fixed order is the one named. Docker runs only for the honest patches and for the "validator not called" check, which uses a mock.
