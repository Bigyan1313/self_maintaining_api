# Decisions — Increment 12: Delivery (branch + PR, flagged findings)

| Date       | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                         | Why                                                                                                                                                                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-11-22 | The GitHub client (`infra/github/client.ts`) exports only `createGitHubClient`, `GitHubError` and two constants. The returned client is frozen and has 11 read/create methods. The Octokit instance never leaves the module.                                                                                                                                                                                                                     | FR-34 / C-02: merge, auto-merge and ref updates are impossible, not just unused. A test checks the export list and the method list.                                                                                                       |
| 2026-11-22 | Defence in depth: every request goes through a transport allowlist (`allowlist.ts`) before `fetch`. Only 12 (method, path) pairs in the one configured repository are allowed. `POST /git/refs` must create `refs/heads/sma/…` (never a protected branch), and `POST /pulls` must have an `sma/…` head. GraphQL, PUT/PATCH/DELETE and other hosts are refused. The path is matched after URL-decoding, because Octokit encodes `/` inside a ref. | Even Octokit's generic `request()` cannot send a merge. The decoded match is how GitHub itself reads the path.                                                                                                                            |
| 2026-11-22 | The protected branches are the stored `default_branch` plus GitHub's live default branch (fetched by `getRepo` before any branch is created).                                                                                                                                                                                                                                                                                                    | The stored value could be out of date.                                                                                                                                                                                                    |
| 2026-11-22 | The happy-path order is `GET repo → GET commit (analyzed) → blobs → tree → commit → create ref → PR → labels`. The prompt says "get ref". We read the repository (live default branch) and the **analyzed commit** (for its tree) instead, because the base must be the analyzed commit, not the current head. `getRef` stays in the client, for resuming a retry and for the live test.                                                         | The Git Data API needs the base tree SHA. The default-branch head is never used as a base.                                                                                                                                                |
| 2026-11-22 | No msw/nock dependency. GitHub is mocked at the `fetch` boundary that Octokit accepts (`test/github-fake.ts`). The fake records every request and can script failures per route.                                                                                                                                                                                                                                                                 | No new dependency (C-07). It sees exactly what would hit the network.                                                                                                                                                                     |
| 2026-11-22 | Missing labels are created with `ensureLabel` (GET label → 404 → POST label; a 422 race is OK) and then added.                                                                                                                                                                                                                                                                                                                                   | FR-35 asks for labels to be created if missing. An explicit colour and description beats GitHub's implicit grey label.                                                                                                                    |
| 2026-11-22 | `deliver` finishes the run: `repaired` + `pr_url` on success, or `stage_failure` with `failure_stage = deliver` on failure. It refuses (throws, no GitHub call) unless the run is unfinished and its **latest attempt passed** with exactly the given patch.                                                                                                                                                                                     | Deliver is the last stage. Only validated patches get PRs, so cheating, failed or refused runs can never reach GitHub (FR-33, FR-36).                                                                                                     |
| 2026-11-22 | **Retry = new child run** (`parent_run_id` = the failed run, `stage_reached = deliver`, no attempts, zero tokens/cost). The failed run's `deliver` row stores the redacted evidence, the source run id and partial GitHub progress (branch, commit, PR). The retry re-reads the patch from the source run's passing attempt row.                                                                                                                 | Finished runs are frozen (FR-39 trigger) and `run_stage_results` allows one row per (run, stage). A child run keeps everything append-only with no migration, and matches the reanalysis pattern. Zero usage avoids double-counting cost. |
| 2026-11-22 | A retry resumes from what already exists on GitHub. An untouched `sma/` branch (head still equals the recorded commit) is reused. A PR that was opened but not labelled only gets labels. Otherwise the retry does a full delivery on a new `sma/run-<childId>-…` branch, rebuilding the files from the stored patch (`patchedFilesFromPatch`: `git apply` in a disposable working copy, no code executed).                                      | No duplicate PRs and no orphaned work. We never update or delete refs.                                                                                                                                                                    |
| 2026-11-22 | If labelling fails after the PR opened, the run is a `stage_failure`, but `pr_url` is still recorded.                                                                                                                                                                                                                                                                                                                                            | The PR exists and must be visible. FR-35 is not yet met, so it is not counted as success until a retry labels it.                                                                                                                         |
| 2026-11-22 | `recordFlaggedFinding({ status, reason })` accepts `flagged`, `failed`, `cheating_rejected` and `aborted`. It writes a `skipped` deliver row (`pullRequest: null`) and finishes the run with `flagged_reason`. It takes no client and reads no credential.                                                                                                                                                                                       | FR-36: structurally 0 GitHub calls. The test also spies on global `fetch`.                                                                                                                                                                |
| 2026-11-22 | The PR title/body template (`buildPrTitle` / `buildPrBody`) and branch rules live in `packages/core/src/delivery/` (new files, new exports only). Evidence JSON is trimmed to 2,000 chars per side. The **tail** of the raw output (6,000 chars) goes in `<details>`. Code fences are longer than any backtick run in the content. The body is capped at 60,000 chars. Fixture runs are labelled (BR-06).                                        | Pure and unit-testable (C-05). The tail holds the test summary. Content cannot break out of its fence. GitHub caps bodies at 65,536 chars.                                                                                                |
| 2026-11-22 | Redaction (`redactForDelivery`) removes the exact token in use, token shapes (reusing `redactRepairSecrets`), `Authorization:` headers and `user:pass@` URL credentials. It runs on the title, the body, every error message, `failure_detail` and (deep) the stored evidence. `GitHubError` carries no `cause`. Octokit logging is silenced.                                                                                                    | NFR-04: the token must not appear in errors, logs, PR bodies or anything later exported.                                                                                                                                                  |
| 2026-11-22 | The commit is built from full file contents via blobs/trees (base64). The mode comes from the working copy. Deletions are tree entries with `sha: null`. There is no `git push`, and a grep test fails the build if `pulls.merge`, `enablePullRequestAutoMerge`, `git push`, a `/merge` route or `updateRef`/`deleteRef` appears in `apps/server/src`.                                                                                           | The prompt forbids token-in-URL pushes. The grep test is the never-merge proof.                                                                                                                                                           |
| 2026-11-22 | Live smoke test `test/deliver.live.test.ts` is skipped unless `GITHUB_TOKEN` and `SMA_DEMO_REPO=owner/name` are set. It delivers the honest rename patch on the repo's current default-branch head and checks open/unmerged/labels/default branch unchanged. It is not run in this increment because no token is configured.                                                                                                                     | Human task: create the demo repo and a fine-grained token.                                                                                                                                                                                |
| 2026-11-22 | Known limit for the orchestrator (Inc 13): a run's `commit_sha` must exist in the GitHub repository. For `demo/consumer` (a folder inside our monorepo) the analyzed commit must be the demo repo's commit, otherwise delivery fails clearly with "analyzed commit … is not in owner/name".                                                                                                                                                      | Delivery must base on the analyzed commit and must not silently switch to the current head.                                                                                                                                               |

No schema migration and no HTTP routes. Wiring delivery into the pipeline belongs to Increment 13.
