# Decisions — Increment 13: Pipeline orchestrator + run records + export

| Date       | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                                                                                                                                                                                             |

| 2026-11-22 | **New migration `0002_spec_check_failure_stage`**: `spec_checks.failure_stage` (the `stage` enum), set exactly when `outcome = 'failed'` and only to `ingest`, `detect` or `classify` (two CHECK constraints). The migration backfills existing failed checks as `ingest` (only ingest wrote checks before). `ingest()` now sets it. A detect/classify failure is a **second** spec-check row (`failed`, same `spec_version_id`) after the ingest row (`changed`). | UC-02's postcondition is "the failure **and its stage** are recorded"; the error text alone would make the stage untyped. Additive, nullable for non-failures, no existing migration edited (rule 9).                                                                                                                           |
| 2026-11-22 | Spec-check trigger is **"ingested version ≠ baseline"**, not ingest's `changed` outcome.                                                                                                                                                                                                                                                                                                                                                                           | `decideCheckOutcome` returns `no_change` for any hash already stored. After a detect failure the new version is stored but the baseline is not advanced, so with an outcome-based trigger a retry would never detect it (FR-11 says failures must be retryable). Tested.                                                        |
| 2026-11-22 | Stage attribution in the spec-check flow: typed oasdiff/parse errors → `detect`; an invalid migration note or a failure after oasdiff returned (classification, persistence, advancing the baseline) → `classify`. The flow wraps the oasdiff runner to know which side of that line a thrown error came from, and reuses `detectAndClassify` unchanged.                                                                                                           | FR-38 / NFR-02 blame the right stage, without copying inc06 logic.                                                                                                                                                                                                                                                              |
| 2026-11-22 | `checkSpec(apiId, source, { migrationNote })` stores an optional migration note for the (baseline → new) pair **before** classification.                                                                                                                                                                                                                                                                                                                           | A note can only confirm mappings during classification, and changes are immutable afterwards (FR-39; the trigger lets only human-confirmation columns change). UC-01 step 3 attaches the note with the configuration. Over HTTP, a later note cannot reclassify; the dashboard (inc14) can use the human confirm-mapping route. |
| 2026-11-22 | The inc04 upload / URL-check / polling routes run the full spec-check flow **only when the app has an orchestrator** (`IngestDependencies.checkSpec`). Responses gain an optional `pipeline` object (`changeIds`, `baselineAdvanced`, `failure`).                                                                                                                                                                                                                  | Keeps inc04's own tests (which expect the baseline to stay put) valid, while the production server (`main.ts`) does UC-02 end to end. Additive contract change.                                                                                                                                                                 |
| 2026-11-22 | **One run at a time: a second request gets `409`** (`RunBusyError`), not a queue. Start/reanalyze/retry-delivery share the lock; spec checks keep their own serial queue.                                                                                                                                                                                                                                                                                          | A run can take many minutes (four Docker validations); a hidden queue would make a request hang with no feedback. 409 tells the dashboard to retry later.                                                                                                                                                                       |
| 2026-11-22 | `POST /api/runs` and `POST /api/runs/:id/reanalyze` return **`202 Accepted`** with the `running` run as soon as its row exists; stages continue in the background, the client polls `GET /api/runs/:id`. `retry-delivery` is synchronous (GitHub calls only).                                                                                                                                                                                                      | Validation can take up to 10 minutes per attempt.                                                                                                                                                                                                                                                                               |
| 2026-11-22 | A run is refused **before any row exists** (404/422) for an unknown change or repository, a repository without `local_path`, or a path that is not a git repository with a commit. A dirty repository is accepted and fails in Locate (`stage_failure`, stage `locate`).                                                                                                                                                                                           | `runs.commit_sha` is NOT NULL and must be a real commit; inventing one would be false evidence. A dirty tree is an "unreadable repository" case NFR-02 wants reported as a stage failure.                                                                                                                                       |
| 2026-11-22 | `is_fixture` = either spec version of the change has `source_mode = 'fixture'`.                                                                                                                                                                                                                                                                                                                                                                                    | BR-06; the change is fixture-derived if either side is.                                                                                                                                                                                                                                                                         |
| 2026-11-22 | `not_affected` and `needs_review` runs store Locate's reason in `flagged_reason`. A change with no HTTP method → `needs_review` with a `skipped` locate row (never `not_affected`).                                                                                                                                                                                                                                                                                | UI-03 wants "the PR link or the reason none exists"; C-01 forbids treating unknowns as not affected.                                                                                                                                                                                                                            |
| 2026-11-22 | `single_shot` runs (B2) are **never delivered**: a passing one finishes `repaired` with a `skipped` deliver row and the reason "Single-shot evaluation run (B2): the patch was scored, not delivered."                                                                                                                                                                                                                                                             | B2 has no cheat guards; opening a PR from an unguarded patch would contradict FR-27–31. Mode exists for the evaluation (inc16). The contract gains an optional `mode` on `StartRunRequest`.                                                                                                                                     |
| 2026-11-22 | Any thrown error inside a stage → a `failed` row for that stage (unless the stage already wrote one) and the run finished as `stage_failure` with `failure_stage`/`failure_detail`. Details are scrubbed with `redactForDelivery` plus every env value whose name looks like a secret (`TOKEN`, `KEY`, `SECRET`, `PASSWORD`, …), the repository's `credential_ref` value, and the `DATABASE_URL` password; capped at 4,000 characters.                             | NFR-02 (no false success, stage named), NFR-04.                                                                                                                                                                                                                                                                                 |
| 2026-11-22 | At startup `main.ts` calls `recoverInterruptedRuns()`: any run still `running` (the server died mid-run) gets a `failed` row for its `stage_reached` and ends as `stage_failure`. Optional `{ repositoryId }` scope, used by the tests because the test database is shared by parallel test files.                                                                                                                                                                 | Without it a run could stay "Running" forever after a restart (DR-01, NFR-02).                                                                                                                                                                                                                                                  |
| 2026-11-22 | Run Detail, JSON export and HTML export are built by one function (`loadRunDetail`): contract shapes, `{ value, label }` for every enum, ISO timestamps, and every string scrubbed. Stage results are ordered by `finished_at` (each stage finished before the next began; repair's row starts before its baseline-validate row but finishes after it). JSON export sorts keys at every level.                                                                     | One builder means the export always matches the DB and the endpoint (FR-41, AT-08).                                                                                                                                                                                                                                             |
| 2026-11-22 | HTML export: inline CSS, a `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'` meta tag (and header on the GET), no scripts, no external resources; every value HTML-escaped; only `https://` PR URLs become links. Each attempt shows its patch and validation output.                                                                                                                                                                       | "No external requests, no scripts"; a stored `javascript:` URL can never become a link.                                                                                                                                                                                                                                         |
| 2026-11-22 | `POST /api/runs/:id/export` writes `run-<id>.json` and `run-<id>.html` into `exports/` (gitignored). Both are written to temp names, then renamed; any failure removes temps and anything already renamed, and returns `500` `[{ field: 'export', … "was not saved" }]`. Success returns `201 { saved: true, json, html }` with file names only (no host paths).                                                                                                   | DR-05: a report that is not fully written is never reported as saved. `SavedExportSchema` added to the contract.                                                                                                                                                                                                                |
| 2026-11-22 | `GET /api/runs` lists newest first.                                                                                                                                                                                                                                                                                                                                                                                                                                | The Runs view (inc14) shows the latest run first.                                                                                                                                                                                                                                                                               |
