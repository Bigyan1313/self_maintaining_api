# Dashboard (Increment 14)

Five React Router views use the shared contract in `@sma/core/api/contract`:
Configuration, Changes, Runs, Run Detail, and Results. State labels come from the
shared domain enums; tables, form labels, status messages and the mapping dialog
remain usable without relying on colour.

## Run with the real server

From the repository root:

```sh
npm ci
npm run consumer:install
npm run db:up
npm run db:migrate
npm run dev -w @sma/server
# In another terminal:
npm run build -w @sma/core
npm run dev -w @sma/web
```

Vite proxies `/api` to `http://127.0.0.1:3000`. Open its printed local URL. Repository
paths refer to the server's filesystem and must be Git repository roots. A credential
field accepts an environment variable **name**, never a token. Upload v1/v2 specifications,
inspect their changes, then explicitly confirm any mapping before permitting repair.
A confirmation is not inferred from field-name similarity.

Run detail polls while a run is active, shows spec/mapping/call-site/coverage/attempt
and validation evidence, and explains absent PRs. Retry delivery is offered only for
a recorded delivery-stage failure. Exports are fetched and validated before download;
failed exports remain visible as errors. Evidence is rendered as escaped text.

`/api/results` is **waiting on Increment 16**. Without it, the real dashboard says so
rather than presenting a fabricated successful evaluation. Empty returned results show
“No evaluation results yet.” Missing metrics are “Not reported,” not zero.

## Development mocks and browser acceptance

Normal development mocks only the unmerged results endpoint:

```sh
VITE_USE_MOCKS=true npm run dev -w @sma/web
```

The complete fixture demonstration requires both explicit flags:

```sh
VITE_USE_MOCKS=true VITE_E2E_FIXTURES=true npm run dev -w @sma/web
```

A visible banner distinguishes these modes. Fixture evaluation numbers are illustrative,
not study results. **Production builds never start the mock worker.** The merged
configuration/change/run routes are not mocked in normal development mode.

```sh
npx playwright install chromium
npm run e2e       # full mocked workflow, downloads, desktop/mobile screenshots
npm run e2e:real  # real server must already be listening on port 3000
```

The real smoke test registers a temporary trusted Git repository, uploads valid specs,
opens/cancels the confirmation dialog, and verifies a completed **unconfirmed/flagged**
run and JSON export. It deliberately makes no model or GitHub calls. It creates append-only
test records with an `e2e-` owner in the configured database; use a development database.
The temporary repository is removed when the test finishes.

CI runs both browser suites after normal tests and migrations. Chromium is pinned via
Playwright 1.65.1. Screenshots for every view, the confirmation dialog, form errors,
and a mobile result page are saved under `docs/acceptance/screenshots/inc14/`.
CI uploads those images plus traces/download evidence as `dashboard-acceptance`.
The real-server screenshot is generated by CI (or the local real suite), not fabricated.

## Additive results contract for Increment 16

Existing `{ label, results }` responses remain valid. Optional `summaries` contains
one `EvaluationSummarySchema` per baseline: detection precision/recall, repair rates
including category breakdown, refusal correctness, attempts distribution, guard counts,
false confidence, and cost/total/model/container time per repair. Rates are fractions
from 0 to 1; nullable metrics mean unavailable. These values must be computed by the
server/evaluator. The browser only formats them.

Optional `failures` is a server-scored list of `{ scenarioId, baseline, reason }`.
The browser must not infer that every refusal is a failed scenario. Rows preserve
partial/excluded labels, exclusion reasons, and human review state. This contract addition
is tested for compatibility and documented in the PR for the inc16 implementer.
